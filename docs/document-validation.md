# 계획 문서 검증 기록

## 2026년 9월 27일 매출배분 계약 검토 반영

- [내부 계약 검토](plans/16-revenue-share-contract-review.md)에 사용자의 최종 정정인 웹 유입 매출 5%, GST 포함 산정 예시, 현재 월매출과 웹 매출 미확인 상태, 비용 부담 방침, 회수 계산과 협상 항목을 기록했다. 그룹 전체 매출 적용이라는 앞선 해석은 현재 기준에서 제외했다.
- README, 일정·비용, 마케팅 측정, 결정 기록과 착수 TODO를 연결했다. 결정 D20~D26에서 사용자 설명·비용 방침·미합의 조건·분석상 제안을 구분했다.
- 클라이언트 제안서 원문과 Word를 버전 1.1로 갱신했다. 15장에 상업 조건 협의 항목을 추가하고, 코드 소유권을 회사로 자동 이전하는 표현을 별도 계약 조건으로 수정했다. 개발자의 시간가치·회수 계산·내부 협상 전략은 클라이언트 제안서에 넣지 않았다.
- README와 docs의 Markdown 21개에서 로컬 링크가 모두 존재함을 확인했다. 정산 예시, 초기 투자 A$50,000, 월 유지관리 시간가치 A$2,400, 회수 기간 83.3·19.2·6.6개월, 24개월 회수 필요 웹 매출 약 A$89,667와 웹 비중 30%일 때 전체 매출 약 A$298,889를 재계산했다. 모두 예시 가정이며 회사 실적 검증이 아니다.
- Word는 기존 `tools/build_client_doc.py`와 번들 Python으로 재생성했다. 원문과 Word의 제목 16개·표 16개, 추가 조건과 삭제한 소유권 단정 표현을 대조했다.
- 번들 `render_docx.py`와 번들 LibreOffice로 최종 Word 16페이지를 PNG 렌더링하고 전 페이지의 한글·표·페이지 경계·링크·마지막 문장을 육안 확인했다. 첫 렌더의 한글 누락은 작업 전용 임시 Fontconfig에 시스템 한글 글꼴 경로와 Malgun Gothic → Apple SD Gothic Neo 대체를 지정해 해결했다. 사용자 앱·시스템 글꼴·공유 런타임은 변경하지 않았다. 표지의 표 넘침과 빈 페이지를 원문 문단 길이 조정으로 수정한 뒤 다시 확인했다.
- QA 중간 파일은 `/private/tmp/lk-contract-doc-qa-verified`, 작업 전 원문 사본은 `/private/tmp/lk-contract-doc-update-before`에 두었다. 기존 ZIP은 수정 전 보관본으로 유지하고 README에 표시했다.
- 이번 확인은 문서·계산·렌더링 점검이다. 계약 체결, 회사 회계 검증, 앱 실행·배포·결제·AI 기능 테스트, 외부 전달은 수행하지 않았다.

## 문서 생성과 렌더링

Word는 번들 Python과 python-docx로 생성했다. 최초 저장 후 콘솔 경로 출력에서 Windows 인코딩 오류가 발생했으나 문서는 정상 저장되었고 출력 코드를 수정했다. 문서 본문 저장 실패는 아니었다.

지정된 render_docx.py는 이 Windows 환경에서 LibreOffice 실행 파일이 없어 실패했다. 오류는 `LibreOffice soffice.exe was not found on PATH`였다. 사용자 설치 LibreOffice를 사용하지 않았으며, 대신 Word의 비표시 문서 열기와 PDF 내보내기를 사용했다. 번들 Poppler와 pdf2image로 전체 페이지 PNG를 생성해 확인했다. 최종 Word와 같은 파일에서 생성한 결과를 검토했다.

검증 PDF·PNG·텍스트·구조 보고서는 tmp/docx-qa에 보관하며 최종 전달 패키지에는 포함하지 않는다. `tools/build_client_doc.py`는 Word 재생성 도구이고 `tools/verify_documents.py`는 문서 링크·계산·구조와 QA 이미지 생성 도구다.
