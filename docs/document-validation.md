# 계획 문서 검증 기록

검증일 2026년 9월 25일. 이번 검증 대상은 계획서·Word 제안서·프로젝트 설정이다. 웹앱 기능 테스트, 실제 결제, AI 모델 성능 평가, 식품 운영 승인은 수행하지 않았다.

## 확인 결과

- 개발 계획서 00~14의 15개 파일과 README, 클라이언트 원문, AGENTS.md를 확인했다.
- ChatGPT 프로젝트의 관련 대화 3개와 이미지 시안 3개를 읽고 기존 결정과 신규 범위를 구분했다.
- ESN은 사용자의 답변에 따라 ERP·CRM 중심으로 반영했다.
- Markdown의 로컬 문서·시안·Word 링크에 존재하지 않는 대상이 없는지 점검했다.
- 단계 공수 850~1,270h, 개발비 A$85,000~177,800, 20% 예비비 포함 A$102,000~213,360을 재계산했다.
- 월 인프라 가정 A$400~1,200, 매체 예산 A$3,000, 가정 매체 CAC A$142.86과 견적 총액 A$473 예시를 재계산했다.
- `.codex/config.toml`의 TOML 문법과 gpt-6-astra/xhigh 값을 확인했다. 실제 실행 중인 대화 모델 변경은 확인하거나 수행하지 않았다.
- 클라이언트 Word는 15페이지이며 전 페이지를 PNG로 렌더링해 한글 표시, 표 경계, 문단 배치, 페이지 번호, 마지막 문장과 링크를 육안 확인했다.

## 문서 생성과 렌더링

Word는 번들 Python과 python-docx로 생성했다. 최초 저장 후 콘솔 경로 출력에서 Windows 인코딩 오류가 발생했으나 문서는 정상 저장되었고 출력 코드를 수정했다. 문서 본문 저장 실패는 아니었다.

지정된 render_docx.py는 이 Windows 환경에서 LibreOffice 실행 파일이 없어 실패했다. 오류는 `LibreOffice soffice.exe was not found on PATH`였다. 사용자 설치 LibreOffice를 사용하지 않았으며, 대신 Word의 비표시 문서 열기와 PDF 내보내기를 사용했다. 번들 Poppler와 pdf2image로 전체 페이지 PNG를 생성해 확인했다. 최종 Word와 같은 파일에서 생성한 결과를 검토했다.

검증 PDF·PNG·텍스트·구조 보고서는 tmp/docx-qa에 보관하며 최종 전달 패키지에는 포함하지 않는다. `tools/build_client_doc.py`는 Word 재생성 도구이고 `tools/verify_documents.py`는 문서 링크·계산·구조와 QA 이미지 생성 도구다.

## 남은 사업 결정

계획서의 미정 항목은 결함이 아니라 착수 때 실제 자료로 확정할 의사결정이다. 실제 서비스 가격·작업 중심 주소·법인/세금·자격·식품 제조와 배송·SKU·광고 예산은 승인된 값이 아니다. [결정 기록](plans/14-decisions-and-sources.md)에서 담당자와 확정 시점을 관리한다.
