# KCP Cinematic Kitchen — WebGL 개정

2026-09-29 · [사용자 제공 프롬프트](../design-assets/cabinet-cinematic-v3/user-brief.txt)를 현재 KCP 상세에 적용한다.

## 범위와 디자인

메인 홈페이지는 서비스 소개 프로토타입으로 유지한다. `/services/cabinet-painting`을 사진 Hero → 9단계 입체 공정 → 전후 비교 → 색상/광택 미리보기 → 재도장/교체 비교 → 마감 디테일 → 기존 서비스·적합성·포함 범위·지역·FAQ → 문의 CTA로 재구성한다. 기존 앵커는 보존한다.

전역 Manrope·버튼·타입 토큰을 재사용하고 KCP에 따뜻한 off-white, charcoal, sage 소재색을 적용한다. 큰 에디토리얼 제목·여백·사진/모델 전체 화면을 중심으로 구성하며 장식 파티클·과도한 회전은 넣지 않는다.

## 연속 공정과 렌더러

Three.js로 같은 캐비넷 모델을 유지하면서 검사 → 분해 → 세척 → 샌딩/국소 패치 → 마스킹 → 프라이머 → 2회 마감 → 건조/경화 → 재조립을 스크롤에 연결한다. 손잡이·힌지는 별도 기하로 분리한다. 기존 사진을 단순 전환하는 방식에서 실제 원근·조명·재질의 WebGL 모델로 확장한다.

실측 GLB/CAD 자료는 제공되지 않았으므로 정면 셰이커 캐비넷 사진에 착안한 파라메트릭 건축 컨셉 모델을 제작한다. 사진과 완전히 같은 실측 모델 또는 실제 시공 결과라고 표시하지 않는다. 실제 회사 프로젝트·시공 전후 자료와 생성 사진/모델을 구분한다.

`src/shared/ui/kitchen-scene`은 렌더러/모델/재질·정규화된 timeline을 맡고 `service-catalog`는 공정 내용·색상 예시·페이지 조립을 맡는다. 렌더러는 progress(0–9), colour, sheen, mode를 받는다. 다른 서비스에는 공용 로딩·수명관리 방식을 재사용하고 모델과 업무 콘텐츠를 별도로 공급하도록 확장할 수 있다. 주방 기하 자체를 모든 핸디맨 작업의 범용 모델이라고 주장하지 않는다.

네이티브 스크롤과 requestAnimationFrame으로 실제 섹션 위치에 연결한다. 스크롤을 가로채지 않고 순방향/역방향·앵커 이동을 동일하게 처리한다. GSAP/Lenis는 결과 구현의 필수 의존성으로 추가하지 않는다. 모델은 코드로 구성하므로 GLB/Draco 다운로드는 없다. 렌더링은 변화/리사이즈에 반응하고 offscreen에서는 멈추며 DPR·그림자 해상도를 제한한다. 라이브러리 지연 로드, 재질·기하 해제와 WebGL 실패 대응을 포함한다.

## 콘텐츠와 상호작용

- 실제 HTML로 H1/H2/H3, 9단계 본문, 서비스 6개, 회사 제공 지역/FAQ를 유지한다.
- Before/After는 드래그와 키보드 range 입력으로 조정하며 생성 컨셉임을 표시한다.
- 6개 예시 색상 + 사용자 색상과 low sheen/satin/semi-gloss를 로컬 모델에 반영한다. 화면색과 실물 도장 견본은 다를 수 있으며 제품/광택 가능 여부는 현장별 확정한다.
- 비용·기간·보증·시공 방법의 조건을 임의 확정하지 않는다. 기존 회사 제공 사실이 일반적인 프롬프트 문구보다 우선한다.
- Free Quote·Upload Kitchen Photos는 기존 사용자 요청에 따라 비활성 준비 상태를 유지하고 실제 연락 경로를 제공한다. 개인정보 입력·파일 전송·AI·예약·결제는 만들지 않는다.
- Preview `noindex` 유지. 운영 도메인/공개 승인 후 canonical·sitemap·구조화 데이터·색인 작업은 별도다.

## 검증 계획

완료 판정은 실제 구현 후 기록한다. lint/type/build와 실제 브라우저 동작은 별도 확인한다. 데스크톱 9단계/역스크롤/직접 앵커/정적 보기, 전후 range, 색/광택 입력, 모바일 세로구성/메뉴/FAQ/앵커, noindex/H1/overflow/콘솔을 확인한다. WebGL 실패·모션 감소에서는 SEO 본문과 정적 사진을 유지한다. 실제 기기·정량 60fps/Lighthouse 측정은 수행 여부를 별도로 표시한다.

## 구현 결과 — 2026-09-29

계획 범위의 구현과 로컬 검증을 완료했다. 공용 `KitchenScene`은 `progress`, `colour`, `sheen`, `mode` 입력으로 공정/쇼룸을 렌더하며 서비스 본문·사진·CTA는 서비스 모듈에서 조합한다. 핸디맨·페인팅에는 공통 토큰과 레이아웃/상호작용 패턴을 재사용하고, 해당 서비스의 장면 모델과 콘텐츠는 별도로 구성한다. 모든 서비스에 캐비넷 기하를 그대로 쓰는 범용 엔진이라는 뜻은 아니다.
