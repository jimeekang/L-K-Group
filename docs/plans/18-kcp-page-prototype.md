## 이번 구현 범위

- 메인 Kitchen Cabinet Painting 카드의 제목·CTA → `/services/cabinet-painting` 이동.
- 공통 헤더·푸터, 홈으로 돌아가는 메뉴, breadcrumb, 사진과 서비스 소개, 서비스 카테고리 설명, 표면 확인 안내, FAQ.
- 사용자 선택으로 두 카테고리안을 합친다: 전체 캐비넷 재도장 / 부분 도장·터치업 / 색상 변경 / 도어·서랍 도장 / 프레임·패널 도장 / 표면 준비·부분 보수. 앞의 세 항목은 프로젝트 유형, 뒤의 세 항목은 대상 표면·작업 범위다. 겹치는 범위는 함께 평가하며 독립적으로 중복 청구하는 패키지를 뜻하지 않는다. 실제 판매 패키지·제공 범위는 회사 확인 전 확정하지 않는다.
- `Free Quote`는 비활성 버튼과 준비 중 안내만 표시한다. 폼·업로드·AI·금액·예약·인보이스·결제·DB·외부 계정 연결은 구현하지 않는다.
- 기존 주방 사진과 생성된 마감 상세 컨셉 사진을 사용한다. 실제 시공 실적이나 전후 비교로 표시하지 않는다.
- 페이지 구조·콘텐츠 검토용 반응형 화면이다. 최종 색상·서체·레이아웃은 후속 디자인 검토에서 변경할 수 있다.

## 구조와 검색 준비

`src/app`은 라우트·메타데이터·모듈 조립을 맡고, 정적 설명은 `service-catalog`의 content/presentation에 둔다. 공통 이미지 경로·크기·alt는 `src/shared/config/assets.ts`에서 교체한다. 정적 소개를 위해 새 DB·Repository·이벤트·미래 기능의 빈 모듈을 만들지 않는다.

페이지 고유 title·description, H1 1개, H2/H3 계층, 서버 HTML 본문, 서비스 내부 링크, 이미지 alt·크기·반응형 최적화를 준비한다. 프로토타입은 `noindex, nofollow`를 유지하며 운영 도메인·canonical·sitemap·구조화 데이터·검색 순위 보장은 추가하지 않는다. 검색 공개는 회사 정보·콘텐츠·도메인·공개 승인 이후다.

참고: [Next.js 메타데이터](https://nextjs.org/docs/app/getting-started/metadata-and-og-images), [Google 검색 기본 가이드](https://developers.google.com/search/docs/fundamentals/seo-starter-guide). 2026-09-27 확인.

## 후속 제품 흐름 — 이번에 구현하지 않음

사용자가 제시한 목표 흐름을 보존한다.

1. Free Quote → 서비스 선택 → 사진 업로드.
2. AI가 사진에서 관찰한 손상의 강도·설명을 출력.
3. 서비스 카테고리 선택 → 승인된 정찰제 기본가격 + 사진 분석에 따른 추가 작업 후보. 추가 범위·금액은 현장 확인과 고객 동의로 조율.
4. 날짜 선택. 다른 고객이 예약한 날짜는 예약 불가로 처리하는 방향이며 동시 요청도 중복 예약되지 않아야 한다.
5. L&K booking calendar에 저장 → 회사가 작업 기간(duration)을 설정 → 전체 기간의 충돌을 다시 검사하고 일정 확정.
6. 인보이스·결제까지 연결.

이는 후속 설계 방향이며 가격표·AI 정확도·예약 정책의 운영 확정을 뜻하지 않는다. 단일 날짜 차단의 대상이 회사 전체인지 팀/작업 자원별인지, 임시 점유 만료, 여러 날 작업 충돌, 결제 시점·예약금·취소 정책은 후속 설계에서 결정한다. 회사가 기간을 설정하기 전 요청과 최종 확정 예약을 구분해야 한다.

기존 [견적·AI·예약 원칙](05-quote-ai-booking.md)은 유지한다. AI가 임의 금액을 만들거나 위험을 확정하지 않으며, 중복 보수비를 합산하지 않는다. 사진 비공개, 승인된 견적 버전 보존, 고객 동의 없는 추가 청구 금지, 원자적 예약 충돌 방지·검증된 결제 결과 연결은 후속 기능의 불변 조건이다. 기존 문서의 결제·확정 순서와 이번 희망 흐름은 실제 기능 착수 때 함께 확정한다.
