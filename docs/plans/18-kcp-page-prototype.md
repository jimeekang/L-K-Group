## 구조와 검색 준비

`src/app`은 라우트·메타데이터·모듈 조립을 맡고, 정적 설명은 `service-catalog`의 content/presentation에 둔다. 공통 이미지 경로·크기·alt는 `src/shared/config/assets.ts`에서 교체한다. 정적 소개를 위해 새 DB·Repository·이벤트·미래 기능의 빈 모듈을 만들지 않는다.

페이지 고유 title·description, H1 1개, H2/H3 계층, 서버 HTML 본문, 서비스 내부 링크, 이미지 alt·크기·반응형 최적화를 준비한다. 프로토타입은 `noindex, nofollow`를 유지하며 운영 도메인·canonical·sitemap·구조화 데이터·검색 순위 보장은 추가하지 않는다. 검색 공개는 회사 정보·콘텐츠·도메인·공개 승인 이후다.

참고: [Next.js 메타데이터](https://nextjs.org/docs/app/getting-started/metadata-and-og-images), [Google 검색 기본 가이드](https://developers.google.com/search/docs/fundamentals/seo-starter-guide). 2026-09-27 확인.

## 후속 제품 흐름 — 2026-09-30 구현 목표로 선택

사용자가 제시한 목표 흐름을 보존하며 순차적으로 구현한다. 문의 접수만으로 목표를 축소하지 않는다.

1. Free Quote → 서비스 선택 → 사진 업로드.
2. AI가 사진에서 관찰한 손상의 강도·설명을 출력.
3. 서비스 카테고리 선택 → 승인된 정찰제 기본가격 + 사진 분석에 따른 추가 작업 후보. 추가 범위·금액은 현장 확인과 고객 동의로 조율.
4. 날짜 선택. 다른 고객의 확정 예약·유효 점유 등 정책상 불가 날짜는 선택할 수 없게 한다. 이때 선택은 희망 시작일이며 회사의 작업 기간·자원 확인 전에는 확정 예약이 아니다.
5. L&K booking calendar에 요청으로 저장 → 회사가 작업 기간(duration)·자원을 설정 → 전체 기간의 충돌을 다시 검사 → 최종 견적·일정 조건의 고객 수락과 필요한 확정 요건을 충족한 뒤 일정 확정.
6. 프로젝트의 마지막 작업 후 사용자가 앱에서 **Complete**를 누르면 최종 인보이스 발행 → **실제 발행일로부터 3일 후 납기** → 결제·입금 상태까지 연결. [27번](27-kcp-google-calendar-sync.md)에 Sydney 기준 달력일 +3과 중복 발행 방지를 명세한다.

2026-09-30 지정 회사 연동 계정은 `Lnkgroupsydney@gmail.com`이다. 근무시간·기간 계산 규칙은 보류하고 정찰제는 가격 자료를 받은 뒤 진행한다. 이번에는 P0 명세만 갱신하며 실제 계정 연결·발행은 수행하지 않는다.

전체 흐름은 사용자 선택이며 가격표·AI 정확도·예약 정책의 운영 확정을 뜻하지 않는다. 단일 날짜 차단의 대상이 회사 전체인지 팀/작업 자원별인지, 임시 점유 만료, 여러 날 작업 충돌, 결제 시점·예약금·취소 정책은 25번 결정·의존성 표에서 관리한다. 회사가 기간을 설정하기 전 요청과 최종 확정 예약을 구분한다.

기존 [견적·AI·예약 원칙](05-quote-ai-booking.md)은 유지한다. AI가 임의 금액을 만들거나 위험을 확정하지 않으며, 중복 보수비를 합산하지 않는다. 사진 비공개, 승인된 견적 버전 보존, 고객 동의 없는 추가 청구 금지, 원자적 예약 충돌 방지·검증된 결제 결과 연결은 불변 조건이다. 예약금이 필요하면 전체 기간 점유·입금 확인 후 확정하고, 필요 없으면 고객 수락·기간 확보 후 확정하여 청구로 이어간다. 적용할 정책은 회사 확인 전 활성화하지 않는다.
