- [ ] 필요 시 Docker 설치·사용하기: Coatly DB 이식이나 반복 초기화·권한 테스트를 로컬에서 실행해야 할 때 도입하기. [로컬 개발 안내](https://supabase.com/docs/guides/local-development)
- [ ] 재사용할 기능을 L&K 프로젝트에 이식하고 회사 이름·로고·사업자 정보·메일·PDF 양식 바꾸기.
- [ ] 회사용 `/admin` 화면과 Supabase Auth 직원 초대·로그인·관리자 MFA·역할별 권한 만들기. 운영 로그인 URL·메일 설정하기.
- [ ] Coatly 데이터 구조를 L&K DB에 맞추고 고객·직원·회사별 접근 권한 확인하기.
- [ ] Cabinet 문의를 관리 웹의 문의함에 연결하고 고객 등록·견적 생성까지 이어주기.
- [ ] Cabinet용 문·서랍·프레임·공정 가격표와 견적 작성·수정·PDF·발송·고객 수락 연결하기.
- [ ] 수락된 견적을 일정·작업 관리에 연결하기. 여러 날 작업과 담당자 일정 충돌 확인하기.
- [ ] 인보이스·입금 기록·미수금·완료 처리를 연결하고 견적과 청구 금액이 일치하는지 확인하기.
- [ ] 메인·Cabinet 문구, 작업사진, FAQ를 수정하는 간단한 콘텐츠 관리 넣기.
- [ ] Coatly의 SaaS 구독·요금제·사용량 제한은 회사 내부 업무에 필요한지 확인하고 제외할 항목 정리하기.
- [ ] 실제 고객 예약금·온라인 결제가 필요하면 Stripe를 별도로 연결하기. Coatly의 SaaS 구독 결제를 그대로 고객 공사 결제로 사용하지 않기.
- [ ] 문의 → 견적 발송·수락 → 일정·작업 → 인보이스·입금 흐름을 회사 담당자가 직접 확인하기.
- [ ] Vercel 운영 설정, 직원 권한, DB·파일 백업, 오류 알림, 간단한 사용법 정리 후 관리 웹 배포하기.

완료 기준: 회사가 Cabinet 문의부터 작업·청구까지 같은 고객 기록으로 처리할 수 있다. 관리 웹 기능은 Coatly 재사용을 우선하며, 필요한 수정량을 확인한 뒤 일정을 확정한다.
