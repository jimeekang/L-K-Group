## DDD와 조립 방식

기존 문서·시안을 보존한 채 저장소 루트에 앱을 추가한다. 비어 있지 않은 루트에 생성 도구를 무조건 덮어쓰지 않는다. 초기에는 모노레포·별도 패키지 배포·DB가 필요하지 않다.

```text
src/app/                         라우트·메타데이터·모듈 조립
src/modules/service-catalog/
  domain/                        서비스 정의·식별자
  application/                   목록 사용 사례·필요한 포트
  infrastructure/                로컬 카탈로그 구현
  presentation/                  서비스 카드·목록
  index.ts                       공개 진입점
src/modules/company-profile/     회사 소개·연락 가능 상태·UI
src/modules/showcase/            컨셉/실제 사례 구분·갤러리
src/shared/ui/                   Button·Container·Section
src/shared/config/               공개 설정·자산 목록·색인 상태
public/images/                   교체 가능한 임시 로고·사진
docs/verification/               실제 검증 기록
```

계층은 실제 역할이 생길 때만 만든다. `domain`은 React·Next.js·Supabase를 모르는 순수 TypeScript다. `application`은 도메인과 필요한 인터페이스만 사용한다. 인프라 구현은 조립 지점에서 주입한다. 모듈 간 참조는 공개 진입점으로 제한하며 공통 UI에 사업 규칙을 넣지 않는다.

예: 메인에서 서비스 목록을 조회해 카드에 전달하고, 이후 Cabinet 상세와 관리자에서 서비스 식별자·정의를 재사용한다. 로컬 데이터를 DB 어댑터로 바꿔도 도메인과 카드 계약을 유지한다. 정적 콘텐츠마다 Entity·Repository·이벤트 버스를 만들거나 미래 업무의 빈 모듈을 만들지 않는다. 업무 의미·불변 조건·소유 경계도 함께 기록한다.

Next.js Server Components를 기본으로 하고 모바일 메뉴 등 작은 상호작용만 Client Component로 만든다. Tailwind와 CSS 변수로 디자인 토큰을 분리한다. 설치 시 공식 문서·npm 안정 버전을 확인하고 실제 버전·lockfile을 저장한다.

## 디자인 방향 초안 — 사용자 검토 전

제안명: **Australian Residential Craft**. 호주 주택의 자연광·목재·도장 마감을 소재로 차분하고 실용적인 분위기를 만든다. 대형 종합건설·신규 주방 제작을 암시하는 사진과 카피는 피한다.

- 색: 따뜻한 화이트 `#F7F5EF`, 차콜 `#202824`, 유칼립투스 그린 `#344F43`, 샌드 `#DFD7C8`. 실제 조합에서 텍스트·버튼 대비를 검사한다.
- 서체: 산세리프 한 계열과 명확한 크기·굵기 위계. Manrope를 후보로 두고 적용 전에 사용권·로딩을 확인한다.
- 형태: 시안의 넓은 여백·그리드·얇은 선·작은 모서리 반경. 자동 슬라이더·큰 애니메이션은 추가하지 않는다.
- 사진: 도장된 주방 캐비넷·자연광 주거 공간·표면 마감. 가짜 고객·현장명·시공 전후 실적·자격 표지를 넣지 않는다.
- 로고: 임시 L&K Group 워드마크와 단순한 건축선 모티프를 생성한다. 최종 브랜드 승인·상표 검토가 끝난 로고로 취급하지 않는다.

프로토타입에 필요한 최소 자산인 로고 1개·공간 이미지 2~3개부터 생성하고 추가 제작은 검토 후 진행한다. 파일별 생성 여부·용도·alt·크기·교체 경로를 자산 목록에 남긴다. 생성 도구의 실제 결과를 저장하며 수작업 도형을 생성 이미지라고 보고하지 않는다.

## SEO와 공개 조건

초기부터 `lang="en-AU"`, 읽을 수 있는 본문 HTML, title·description·H1, 의미 있는 서비스 링크, 이미지 크기·alt·`sizes`를 준비한다. 첫 화면 핵심 이미지만 우선 로딩하고 나머지는 지연 로딩한다.

현재는 `noindex`다. 회사 정보·서비스 범위·운영 도메인·공개 승인을 확인한 뒤 색인·canonical·sitemap·적합한 구조화 데이터를 활성화한다. 시안의 `lkgroup.com`이나 localhost를 운영 canonical·sitemap에 넣지 않는다. 도메인이 없을 때 sitemap은 공개 URL을 내보내지 않는다. 구조화 데이터에 미확정 주소·연락처·평점을 넣지 않는다.

robots.txt 차단만으로 색인 제외를 보장하지 않는다. 크롤러가 `noindex`를 읽을 수 있어야 한다. Preview 접근 제한과 색인 정책은 역할이 다르며 `noindex`는 인증 수단이 아니다.

상위 순위를 보장하지 않는다. 실제 사례·승인된 지역·서비스 설명·빠른 모바일 화면을 쌓고, 공개 후 Search Console로 색인·노출·클릭을 확인한다. 지역명만 바꾼 복제 페이지나 가짜 리뷰를 추가하지 않는다.

근거: [Google SEO 안내](https://developers.google.com/search/docs/fundamentals/seo-starter-guide), [noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [Node.js 지원 상태](https://nodejs.org/en/about/previous-releases). 2026-09-27 확인.

## 검증·인수 기준

1. 생성 후 lint·타입 검사·production build·HTTP 응답 확인. CI 파일 생성과 GitHub CI 실행 통과는 구분한다.
2. 1440px·768px·390px·320px에서 메뉴·카드·줄바꿈·가로 넘침을 실제 브라우저로 확인한다.
3. 메뉴 열기·닫기·키보드·Escape·포커스, 모든 앵커·CTA 도착점, 연락처 미등록 상태를 확인한다.
4. 콘솔·네트워크 앱 오류, 이미지 실패, 404, hydration 오류를 해결한다. 컨셉 이미지를 실제 실적으로 표시하지 않았는지 확인한다.
5. HTML 제목·H1·언어·robots·이미지 속성, 도메인 미설정 시 허위 canonical·sitemap URL이 없는지 검사한다.
6. 디자인 적용 후 변경 화면·핵심 동작·성능·접근성을 다시 확인한다. Lighthouse와 실제 이용자 Core Web Vitals는 구분한다.

실패 해결·관련 재검증 전에 의존 단계로 넘어가지 않는다. 외부 자료 대기는 코드 오류와 구분해 기록한다. 문서 점검만으로 앱 QA를 통과했다고 표시하지 않는다.

## 착수 환경과 남은 결정

- Node.js `v24.14.1`, npm `11.11.0` 확인. Node.js 24는 공식 지원표상 LTS다. 실제 사용할 patch 버전은 설치 시 확인한다.

- 기존 문서·산출물의 작업 중 변경을 확인했으며 보존한다.
- 현재 채팅 모델·effort 전환 전용 도구는 없다. 2026-09-27 후속 지시로 서브에이전트도 업무별 Astra xhigh / Sol xhigh를 적용하도록 갱신했다. 구현은 Sol xhigh 서브에이전트의 명시적 모델 선택으로 진행하고 설계·QA와 구분한다. 기존 실행 방식 확인 대기는 해소됐다.
- 실제 연락처·회사 계정 승인·운영 도메인·사진은 대기다. 로컬 프로토타입은 가능하나 고객 연락·공개 배포 완료로 볼 수 없다.
- 검색 아이콘 생략과 디자인 방향은 제안이다. 검토 전 최종 승인으로 취급하지 않는다.
