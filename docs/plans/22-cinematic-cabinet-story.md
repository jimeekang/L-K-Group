# KCP 상세의 사진형 첫 화면과 전체 화면 공정 연출

> 2026-09-28 후속 개정: 공정 사진·6개 도어 마스크·깊이 및 절제된 UI는 [23번 명세](23-front-cabinet-depth-story.md)가 우선한다. 이 문서의 이전 7개 마스크·격자·기술 주석 연출은 제작 이력이다. KCP Hero와 메인 프로토타입 범위는 유지한다.

2026-09-28 · 사용자 추가 요청에 따른 구현 명세. [20번 계획](20-scroll-storytelling-implementation-plan.md)의 배치·연출 관련 항목을 아래 범위에서 갱신한다.

## 사용자 결정

- **최종 사용자 정정:** Kitchen Cabinet Painting 상세 페이지를 변경한다. 메인 홈페이지는 기존 프로토타입으로 남긴다. 앞선 홈페이지 중심 변경 해석은 폐기한다.
- 승인된 사진형 첫 화면 디자인을 KCP 상세에 적용하고 제목·본문·링크를 캐비넷에 맞춘다.
- 전체 7단계는 상세에 유지하되, 좌우 사진/글 구성을 전체 화면 사진과 시공 과정을 보여 주는 강한 연출로 바꾼다.
- 사진을 채우고 분해·준비·도장·조립의 변화와 공정별 세부 표시를 강화한다. 새 견적·예약·결제 기능이나 공개 배포는 포함하지 않는다.

## 메인과 KCP 첫 화면

메인은 기존 서비스 카드·회사 소개·갤러리·연락 중심 프로토타입으로 복원한다. 사진형 HomeHero와 새 teaser를 메인에 추가하지 않는다. 전역 색상·서체·공용 UI는 재사용한다.

KCP Hero H1은 `KITCHEN. RENEWED.`와 보이는 서비스/지역 설명으로 구성한다. 헤더는 해당 페이지에서만 사진 위에 겹친다. Breadcrumb·기존 SEO 소개·범위 설명·준비 안내·실제 연락 링크는 보존한다. Free quote는 준비 안내를 연결한 native disabled 버튼이다.

첫 사진 화면과 목차 다음에 공정 스토리를 배치해 다음 스크롤부터 변화를 경험하게 한다. 서비스·적합성·포함 범위·지역·예시·FAQ·견적 상태의 본문과 8개 ID를 유지하고 공정 이후에 배치한다. 목차 순서는 새 화면 순서에 맞춘다.

## 공정 연출

데스크톱에서는 공정 구간 안의 사진 무대가 화면 전체를 채우고 머문다. 7개 설명은 여전히 서버 HTML의 순서 있는 목록으로 스크롤된다. 밝은 그레이지 그라데이션이 왼쪽 본문을 받치며, 오른쪽 사진과 분리 부품은 넓게 보인다. 작은 사진 카드와 별도 흰색 설명 칼럼은 사용하지 않는다.

사진·문짝 마스크·주석은 동일 좌표 평면 안에서 함께 확대한다. 한 평면 전체를 viewport에 맞춰 crop하며, 사진별 독립 crop으로 부품 좌표가 어긋나지 않게 한다. 공정별 이름·번호·진행 표시·얇은 안내선은 설명을 돕는 그래픽이다. 실제 치수·공학 도면·현장 기록으로 표시하지 않는다.

| 단계 | 시각 변화 |
| --- | --- |
| 01 기존 상태 | 크림색 기존 주방을 넓게 보여 주고 확인할 표면을 표시 |
| 02 탈거 | 원본 사진에서 분리한 7개 도어/서랍 영역이 여러 방향으로 펼쳐짐. 고정 주방은 유지 |
| 03 준비 | 같은 작업장 문짝의 낡은 상태에서 샌딩·패치 상태로 변환 |
| 04 언더코트 | 동일 문짝 위에 기초 도장이 진행되는 reveal |
| 05 마감 | 한 단계 안에서 1차·2차 마감 상태와 진행 구간 표시 |
| 06 재조립 | 분리 부품이 맞춰지고 원본 완성 사진으로 정착 |
| 07 완료 | 완성된 주방과 관리 안내로 마무리하고 일반 페이지로 이어짐 |

색상·폰트·굵기는 기존 전역 토큰을 유지한다. 제목을 키우고 여백과 큰 공정 번호로 장면별 리듬을 만든다. 자동 재생·강제 스크롤·휠 가로채기는 넣지 않는다. 큰 화면에서만 자연스러운 확대·부품 이동·회전·도장 전환을 강화한다.

## 자산 정합성과 표현 한계

내장 image_gen으로 만든 투명 부품은 고정 프레임 포함·좌표 변형 때문에 검수에서 제외했다. 사용 중인 방식은 원본 사진의 도어/서랍 영역을 CSS clip-path로 제한하고 움직이는 사진 레이어다. 캐비넷 자체를 CSS나 SVG 도형으로 그린 것이 아니다.

손잡이는 도어 사진에 포함돼 함께 움직인다. 가려진 힌지와 손잡이를 독립적으로 탈거하는 정밀 애니메이션은 구현 완료로 표시하지 않는다. 이를 추가하려면 같은 좌표의 손잡이 없는 도어와 정확한 철물 자산이 필요하다. 현재 단계 설명은 실제 철물 처리 범위를 회사와 확인하도록 유지한다.

모든 생성 주방·작업장 사진은 설명용 컨셉이며 실제 L&K 시공 증거가 아니다. 회사 제공 실제 사진은 별도 갤러리에 유지한다.

## 재사용과 검증

공용 ServiceStory는 scene 배열·사진·마스크·주석·연출 preset을 받는다. Cabinet 내용과 회사 사실은 service-catalog 콘텐츠에 둔다. 공용 컴포넌트에 Cabinet 전용 분기나 회사 연락처를 넣지 않는다.

모바일·낮은 화면·reduced-motion·JavaScript 차단에서는 각 단계의 사진과 본문을 정적으로 읽는다. 향상 기능이 실패해도 제목·7단계·기존 8개 목차·FAQ·연락 경로가 남는다. 모션 끄기·건너뛰기·직접 단계 링크를 유지한다.

최종 판정은 새 화면의 실제 브라우저 확인과 lint·타입·production build로 한다. 이전 좌우 배치의 QA를 이 디자인의 통과로 인용하지 않는다. 프레임 정합성, 읽던 위치, 반응형, 이미지 실패, 콘솔 및 자산 요청을 다시 확인하고 검증 기록에 미수행 항목을 구분한다.
